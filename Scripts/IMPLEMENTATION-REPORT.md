## 🎯 关键创新

### 1. 三层开关控制架构

```
┌─────────────────────────────────────┐
│  总开关 (ENABLE_PLUGIN)             │ ← 第一层：全局控制
├─────────────────────────────────────┤
│  功能开关 (FEATURE_X_ENABLE)        │ ← 第二层：模块级控制
│  - 签到/抽奖/净化/比价...           │
├─────────────────────────────────────┤
│  调试模式 (DEBUG_MODE_ENABLE)       │ ← 第三层：日志输出控制
└─────────────────────────────────────┘
```

### 2. 三阶段执行模型

```
DNS 预热 (5s) → 主流程执行 → 清理阶段 (3s)
     ↓              ↓              ↓
  解决慢速      并行/串行       资源释放
  DNS 问题      任务调度        状态保存
```

### 3. 黑盒引擎包装器

支持外部混淆引擎（如 qdreader）的注入：

```javascript
function injectExternalEngine(config) {
  // 1. 设置全局参数
  globalThis.$argument = JSON.stringify({
    DEBUG_MODE: config.debugMode ? 'true' : 'false',
    ...config.featureFlags
  });

  // 2. 注入引擎 IIFE
  eval(engineBlob);

  // 3. 返回永不 resolve 的 Promise（异步等待）
  return new Promise(() => {});
}
```

## 🔧 技术细节

### 统一参数规范

所有 Pro 版本插件遵循以下结构：

```ini
[Argument]
ENABLE_XXX=switch,"true","false",tag=总开关
XXX_CRON_EXP=input,"0 12 * * *",tag=Cron 表达式
TIMEOUT=input,180,tag=超时时间 (秒)
XXX_FEATURE_A_ENABLE=switch,"true","false",tag=功能 A
XXX_FEATURE_B_ENABLE=switch,"true","false",tag=功能 B
XXX_DEBUG_ENABLE=switch,"false","true",tag=调试模式
```

### Enable 条件语法

```javascript
// 单条件
enable={ENABLE_XXX}

// 多条件（AND 关系）
enable={ENABLE_XXX}&{FEATURE_A_ENABLE}

// Cron 任务参数传递
cron {CRON_EXP} script-path=xxx.js, 
  argument=[{DEBUG_MODE},{FEATURE_A_ENABLE},{FEATURE_B_ENABLE}],
  enable={ENABLE_XXX}
```

## 🛡️ 安全与合规

### 供应链治理

- ✅ 所有第三方引擎必须在 `ENGINE-MANIFEST.json` 中登记
- ✅ CI/CD 强制校验 blob hash 完整性
- ✅ 引擎变更必须同步更新上游来源和 commit hash

### 已知风险

| 风险项 | 影响 | 缓解措施 |
|--------|------|----------|
| 第三方引擎信任链 | 拥有完整 HTTP 能力 | Hash 校验 + 代码审计 |
| Cookie 泄露 | 锁屏通知可见 Token | 系统级通知隐藏 |
| 混淆代码不可审计 | 静态分析困难 | 动态沙箱测试 |
