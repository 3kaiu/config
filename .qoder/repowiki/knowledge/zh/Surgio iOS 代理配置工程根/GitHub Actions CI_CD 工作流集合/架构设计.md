本模块由 8 个独立的 YAML 工作流文件组成，按职责划分为四类：
- 质量门禁类：`config-validate.yml`（PR/Push 触发，执行插件元信息检查、script-path URL 可达性、Loon/QX 双端规则交叉核对、银行域名 MitM 冲突检测、HTTPDNS rewrite 对齐、Snippet 内容级 diff、Qidian 引擎完整性校验、版本号一致性、QX 规则顺序防遮蔽）；`script-tests.yml`（Node.js 20 沙箱运行 `test/run-tests.js` 回归测试）。
- 资源镜像类：`mirror-scripts.yml`（每日 03:00 UTC 拉取第三方脚本/规则/rewrite 模块/NSRingo bundle，经 node --check、体积≥200B、非 HTML 三重门控后写入 `Mirror/MANIFEST.json`，通过 PR 提审而非直推 main）；`sync-kelee.yml`（每日 02:00 UTC 同步 `Prevent_DNS_Leaks.plugin`）。
- 健康监控类：`upstream-health.yml`（每日 02:17 UTC 探测 ddgksf2013、Maasea、app2smile、blackmatrix7、ws.wenn.in CDN、NSRingo 等 20+ 上游 HTTP 状态码，失败时创建带标签的 Issue）；`cdn-verify.yml`（每日 02:34 UTC 对比 ws.wenn.in 内容与仓库 sha256，不一致则开 Issue + 可选 Bark 推送）。
- 分发部署类：`pages-deploy.yml`（main 分支 push 时通过 `actions/deploy-pages@v4` 发布到 GitHub Pages 作为 ws.wenn.in 故障兜底）；`surgio-build.yml`（监听 surgio.conf.js/template/provider/package.json 变更，用 `npx surgio generate` 重新生成 Profile/Loon.lcf 和 Profile/QX.conf 并自动提交）。
所有工作流均使用 `ubuntu-latest` runner、`actions/checkout@v5`，通过 `$GITHUB_STEP_SUMMARY` 输出 Markdown 表格报告，并通过 `actions/github-script@v7` 在失败时创建带特定 label 的 Issue。
